# Домашнее задание 1: свежие вопросы и ReAct-агент

## Кратко

В работе расширен стартовый датасет свежих вопросов русскоязычными вопросами о событиях 2026 года и проверено, может ли агент на дешёвой модели с инструментами поиска отвечать лучше и дешевле, чем сильная модель без инструментов.



## Датасет

Я выбрал вариант расширения стартового датасета: добавил 20 собственных русскоязычных вопросов, собирал их с рускоязычный вики

Темы вопросов:

- спорт;
- Формула-1;
- киберспорт;
- кино;
- технологии;
- космос;
- политические события;
- медийные события.

Каждая запись содержит поля:

```json

  "id": "...",
  "source": "fresh",
  "question": "...",

  "evidence": "...",

  "url": "..."

```

## Вывод по результатам

На моём наборе тезис курса подтвердился,
Дорогая модель без инструментов ответила верно только на 10% вопросов, добавление русского поиска подняло качество до 40%, а добавление чтения полной страницы через `page_find` — до 60%.
Причем сама модель не смогла ответить всего на 3 вопроса, остальные ошибки из-за проверки ответа. 

Таким образом, агент на дешёвой модели оказался не только точнее, но и примерно в 49 раз дешевле по цене верного ответа.
+ Для средней модели нужно лучше наладить request, т.к падала по 429 ошибки и почему-то не обращалась к инструментам (возможно стоит улучшить системный промпт).

## Разбор провалов

### Провал 1: `fresh-128`

Вопрос:

```text
Кто одержал победу в первой гонке сезона Формулы-1 в 2026 году?
```

Ожидаемый ответ:

```text
Джордж Расселл
```

Что произошло:

- `ru_web_search` нашёл правильную статью: `Формула-1 в сезоне 2026`;
- агент вызвал `page_find` с ключевыми словами про первую гонку и победителя;
- `page_find` не нашёл нужный фрагмент;
- агент сделал дополнительные поисковые запросы;
- в итоге вернул `информация недоступна`.

Причина ошибки:

```text
retrieval/page_find не достал нужный фрагмент из статьи. Ошибка не в генерации, а в поиске нужного места на странице.
```

Что можно улучшить:

- искать не только точные ключевые слова, но и формы слов/корни;
- возвращать больше контекста из полной статьи;
- отдельно обрабатывать таблицы Wikipedia.

---

### Провал 2: `fresh-133`

Вопрос:

```text
Сколько составила общая протяжённость дистанции Тур де Франс 2026?
```

Ожидаемый ответ:

```text
3333 км
```

Что произошло:

- `ru_web_search` нашёл статью `Тур де Франс 2026`;
- `page_find` по ключевому слову `дистанция` не нашёл фрагмент;
- следующий поиск ушёл в более общую статью `Тур де Франс`;
- агент вернул `Информация недоступна`.

Причина ошибки:

```text
инструмент чтения страницы оказался слишком простым и не нашёл нужный фрагмент внутри статьи.
```

Что можно улучшить:

- искать по нескольким синонимам: `дистанция`, `протяжённость`, `маршрут`, `км`;
- извлекать данные из таблиц;
- возвращать соседние абзацы вокруг найденных совпадений.

## Итог

Работа показывает, что для свежих фактов сама модель без инструментов недостаточна. Доступ к поиску и чтению страницы заметно повышает качество, а дешёвая модель с инструментами может быть эффективнее сильной модели без доступа к источникам.
